# Field

Connects a control to its label, supporting text, and validation feedback.
The root shares field state; you choose the layout and render the messages.

## Usage

<div style={{ overflowX: "auto" }}>

```tsx
import { Field } from "@workspace/ui-react/components/field";
import { Input } from "@workspace/ui-react/components/input";

<Field className="grid gap-2">
  <Field.Label>Full name</Field.Label>
  <Input name="name" autoComplete="name" placeholder="Alex Morgan" />
  <Field.Description>Visible on your profile.</Field.Description>
</Field>
```

</div>

## Required

`Field.Label required` adds an asterisk only. Put `required` on the control to enforce the constraint.
For example, using the imports above:

<div style={{ overflowX: "auto" }}>

```tsx
<Field className="grid gap-2">
  <Field.Label required>Email</Field.Label>
  <Input name="email" type="email" autoComplete="email" required />
</Field>
```

</div>

## Errors and states

`invalid` on the root exposes invalid state to integrated controls; it does not create an error message.
`Field.Error` always uses `match={true}` internally: mount it only when an error is present.
Disabling the field does not hide an error that remains rendered.

<div style={{ overflowX: "auto" }}>

```tsx
<Field invalid className="grid gap-2">
  <Field.Label>Full name</Field.Label>
  <Input name="name" autoComplete="name" />
  <Field.Error>Enter your full name.</Field.Error>
</Field>
```

</div>

## Composition

`Input`, `PasswordInput`, `Select`, `Combobox`, `Switch`, and `Checkbox` integrate with Field through Base UI.
Set shared `disabled` and `invalid` state on the root, and arrange the label and control with layout classes.
For `PasswordInput`, also pass `disabled` explicitly to disable its visibility toggle; root state alone does not disable that button.

Place a checkbox or switch beside its label, with help and errors aligned below the label:

<Canvas of={FieldStories.CheckboxField} />

`Textarea` is a native control without automatic Field integration. Connect `Field.Label htmlFor` to the textarea's `id`;
assign IDs to the description and any rendered error, and reference them with `aria-describedby` on the textarea.
Pass `aria-invalid` and `disabled` directly to `Textarea`; root state alone does not configure it.
Only include the error ID in `aria-describedby` while that error is rendered.
